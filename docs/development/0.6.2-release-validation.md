through [PR 95](https://github.com/klimPaskov/HOI4-Mod-Setup/pull/95).

disposable GitHub-hosted runners. The user's desktop, installed app, original

version metadata edits, Git, and retrieving sanitized evidence.

## Release gates and limits

The 0.6.2 release PR reruns the complete remote CI and security gates, including
the version-bound native wizard scenarios. Publication uses the unchanged
protected annotated-tag workflow: source gates, four native builds and
installer lifecycle checks, signature verification, updater signature
verification, exact asset curation, and remote uploaded-byte verification.
Only then may its draft become public. No old tag or release is reused.

The public set is five installers, `latest.json`, and two macOS updater
archives. SBOM, notices, hashes, build identity, and signature evidence stay
in workflow artifacts. Community Windows packages use the ChaosX certificate;
macOS packages are ad-hoc signed and are not Apple-notarized. Linux packages
and every update artifact use the existing Tauri updater key.

There is no schema migration or credential-store change. Confirmed source
selection, checksum verification, conflict review, journaled apply, and
rollback remain mandatory. Source, integration, and remote-harness audits
found no blocking regression in the scoped change.

AI semantic responses in native acceptance use a loopback test provider, not
real account authentication. Real provider logins, paid generation, HOI4
launcher/gameplay, and full native macOS/Linux wizard automation are not
claimed. Existing experimental account and platform limitations remain.

The owning skills were updated with the implementation. This release-only
version/documentation change adds no recurring workflow, command, invariant,
or platform route, so no additional skill change is needed.
