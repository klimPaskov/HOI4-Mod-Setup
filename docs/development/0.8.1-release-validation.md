# 0.8.1 release validation

This patch release fixes a first-run blocker. Its release pull request, the
subsequent `main` checks, and the annotated `v0.8.1` tag workflow are
authoritative for their exact revisions and final publication. This record does
not claim signing, native-package, or publication results before those gates
finish.

## Changes since 0.8.0

- **Python is found where installers put it.** Python 3.14 from the Python
  install manager leaves only app-execution aliases on PATH, which the lookup
  rejected, so setup said Python was missing and blocked installation. The new
  `python_lookup` module also searches the install manager's, the classic
  installers', Program Files, framework and Homebrew folders, tries candidates
  until one is python.org's and 3.9 or newer, and names what it skipped. The
  development-tools step shares the search.
- **A missing Python never blocks installation.** The review shows a warning;
  HOI4 Agent Tools stays incomplete and Repair finishes it.

## Evidence

- Rust (769 desktop tests), front-end (259), clippy, lint and the Windows,
  macOS and Linux CI jobs passed on PR 133.
- Not reproduced on a Python install manager machine; the cause was confirmed by
  reading the lookup. The `Candidate acceptance (new)` and `(kaiserreich)` jobs
  fail on `main` before and after this change (readiness after the pinned
  update) and are not part of this release's fix.
