# 0.6.1 release validation

This record separates observations from final release gates. The checks on
[PR 90](https://github.com/klimPaskov/HOI4-Mod-Setup/pull/90), subsequent main
checks, and annotated-tag workflow are authoritative for the final revision,
signatures, updater metadata, remote asset verification, and publication.

All application launches, builds and runtime tests for this follow-up use
disposable GitHub-hosted runners. The user's desktop, original Workshop mods,
provider accounts and credentials are not used. Local work is limited to
source/document edits, formatting, Git and evidence retrieval.

## Reported and reproduced failures

- The supplied non-English Windows report correctly identified English-string
  classification of filesystem errors. Typed I/O errors now retain ErrorKind
  and raw Windows codes through atomic writes and the verified source cache.
  Tests cover localized messages, spoofed English/code text, Windows missing,
  exists, access and sharing codes, and a cold cache download/reuse sequence.
- Published v0.6.0 reached Ready for new and full Kaiserreich projects under
  Node 24, then exposed missing fresh maintenance scan evidence and checksum
  misuse of a kept generated descriptor. Both are fixed without fabricating
  replacement bytes or weakening source verification.
- The same immutable MCP package produced different optional-dependency trees
  under npm 10 and 11. Clean remote matrix runs identified Windows npm 11 and
  Linux npm 10 as the matching toolchains. Source PR 25 pins private npm per
  platform; it does not replace ambient npm or bless changed package hashes.

## Audits and limits

Security, source, transaction, analysis-boundary and platform/release handoffs
were reviewed. Typed errors are sanitized once at the maintenance IPC boundary;
sign-in, usage-limit and stale-review states stay distinct. There are no
persisted schema or migration changes, no new credential persistence, and no
changes to backup, journal, apply, success-lock or rollback invariants.

The source, transactions, testing, integration and release skills were updated
for the changed recurring boundaries. The README links the approved video and
uses the exact supplied thumbnail. The source bootstrap's preexisting output
buffering and Node publisher-check ordering limits remain documented.

The Local planner fixture does not prove live hosted authentication, model
quality, paid image generation, HOI4 launcher/gameplay, Meshy or Blender use.
No native Russian-language Windows session was run; the filesystem regression
tests are language-independent and include real Windows error codes. Fresh
manual browser/device-code completion, Windows/macOS vault round trips and
updater replacement/retry are not inferred from package or wizard checks.

The user authorized a one-time maintainer merge exception for PR 90 only after
all checks and audits pass. Repository protections remain unchanged. Publish
only from the verified main commit's annotated `v0.6.1` tag through the existing
gated signing, eight-asset curation and remote draft-byte verification workflow.
