# 0.8.0 release validation

This minor release makes updates and the package's new development tooling work
without hand steps. Its release pull request, the subsequent `main` checks, and
the annotated `v0.8.0` tag workflow are authoritative for their exact revisions
and final publication. This record does not claim signing, native-package, or
publication results before those gates finish.

## Changes since 0.7.1

- **Instruction files on update.** `CLAUDE.md` and `AGENTS.md` are updated with
  a three-way merge: the app rebuilds what the old template adapted to (from
  the exact revision and hash the lock recorded) and decides from three byte
  strings. An untouched file takes the new adaptation without a question; a mod
  with its own rules keeps them and gains the new section; an edited file is a
  reviewed conflict that now offers **Merge**.
- **Development tools step.** When an install, update, or repair leaves
  `.tools/check.py`, the app runs the package's own
  `python -B .tools/check.py setup --save-game-dir <folder>` once after the
  apply, as one reviewed action, and records the new hashes of the tracked files
  it regenerates (an allowlist). The step never fails the installation; the
  Ready screen shows a non-blocking **Development tools** line.
- **Tool settings.** `project_label`, `id_prefix` and `shared_registry_prefix`
  in the package's asset and gfx settings files are filled from the mod's name
  and script prefix.
- **Free assistant.** A hosted analysis may take five minutes instead of two;
  the relay (deployed separately, already live) asks the free model to reason
  less, so reviews of installed projects complete reliably.

## Evidence

- Update, live on Windows release builds with the free assistant: a mod
  installed from package revision 9799c33 and updated to Latest planned **zero
  conflicts**, with the instruction files as Merge operations; after applying,
  section 4a was present, the moved rules were in place, the project name was
  kept, and `CLAUDE.md` equalled `AGENTS.md`. A copy with an added custom rule
  showed one conflict with **Merge** offered; after Merge the rule and section 4a
  were both present, and the untouched `AGENTS.md` merged automatically.
- Development tools step, live: a fresh install wrote `.tools/local_settings.json`
  with the plain game folder, added the ignore entries, recorded the regenerated
  agent map in the lock (Ready: managed files pass), and `check.py full` exited 0.
  Repair re-ran the step and turned `incomplete` into `ready`. On a brand-new
  user profile with no Python packages, an update to package revision 4d9b309
  installed them and reported `ready` on the first run (the package's own first-run
  `doctor` bug found here was fixed upstream).
- Pull requests 125 to 129 passed every required check (macOS Intel disk-image
  bundling failed intermittently on the runner and was rerun or overridden; the
  same job passed on other runs).

## Not covered by this record

- macOS and Linux behaviour of the finishing step and of Python discovery were
  not driven by hand. The step uses the Python on `PATH`; a missing Python is
  reported on the Ready screen, never as a failure.
- The step runs after the transaction, so rolling back a finished installation
  does not undo its regenerated files; this is documented in the transactions
  skill.
- The package's `hoi4-agent-tools` workspace registration (`modRoots`) is a
  user-level setting this app does not edit; `doctor` prints the fix.
- Signing, notarization, native package smoke tests, and publication are the tag
  workflow's gates and are recorded by that run.
