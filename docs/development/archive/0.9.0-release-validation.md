# 0.9.0 release validation

This minor release installs hoi4-imagegen-mcp as the image provider and retires GPTImage. Its release pull request, the subsequent main checks, and the annotated v0.9.0 tag workflow are authoritative for their exact revisions and final publication. This record does not claim signing, native-package, or publication results before those gates finish.

## Changes since 0.8.5

- **Release-binary image route.**
  - A manifest may declare a `release_binary` image provider. It has per-platform archives of klimPaskov/hoi4-imagegen-mcp, each with its URL, SHA-256, size, archive kind and archive entries.
  - Setup downloads only the declared GitHub release URL. It checks size and SHA-256 before opening the archive, and extracts only the two declared programs, refusing traversal, links and oversized entries.
  - It installs them in `.tools/image_generation/hoi4-imagegen/<version>/`. It then checks `hoi4-imagegen --version`.
  - It updates side by side and removes the old version only while its files still match the lock.
  - Released 0.8.5 and older builds reject a manifest with this route, so this release has to be out before the kit publishes it.
- **Client entries.**
  - `hoi4_imagegen` goes into every project-level client file: `.mcp.json`, `.vscode/mcp.json`, `opencode.json` and `.codex/config.toml`.
  - User entries are kept. A managed GPTImage entry is replaced.
- **ChatGPT sign-in.**
  - The Ready screen shows the program's own risk note.
  - After confirmation, it runs `hoi4-imagegen login --accept-risk` and reports `login-status`.
  - Setup never sees the tokens.
- **API keys.** Keys stay in the OS credential store, and the program reads them there itself.
- **GPTImage retired.**
  - Its installer and bootstrap are removed.
  - A saved GPTImage choice becomes hoi4-imagegen when the manifest offers it.
  - A manifest that offers only GPTImage installs no image provider and says why.

## Evidence

- **The change merged as #148.**
  - All ten required checks were green: repository-integrity, frontend, Rust on three systems, fuzz compilation and the four Desktop E2E jobs. The other CI jobs passed as well, except the candidate acceptance jobs.
  - Those four jobs run the built app against the live kit manifest. It still offered only GPTImage, so the new app had no default image route to select.
  - They are expected to pass once the kit publishes the hoi4-imagegen route, which depends on this release. They are rerun on main after the kit switch.
- **Local runs on Windows** (on the merged branch):
  - `cargo fmt --check`
  - `cargo clippy --workspace --all-targets --all-features -D warnings`
  - `node scripts/run_rust_tests.mjs --no-fail-fast`
  - `pnpm lint`, `pnpm typecheck` and `pnpm test`
  - Playwright browser tests (34 passed)
  - `pnpm test:released-harness`
  - `scripts/validate_repository.py` and the manifest evidence tests
- **The hoi4-imagegen v0.2.0 release** is the first published binary:
  - five archives with SHA256SUMS and GitHub build attestations
  - the Windows archive downloaded, checked against SHA256SUMS, attestation-verified, and run (`--version` reports 0.2.0)

## Not covered here

- Signed native packages, notarization and updater replacement are left to the tag workflow and its jobs.
- A real browser sign-in through Setup's Ready screen, and an install of the real release through the desktop app, are not covered.
