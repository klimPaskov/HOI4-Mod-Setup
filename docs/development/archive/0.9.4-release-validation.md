# 0.9.4 release validation

This release downloads the kit once as an archive instead of about 1,700 single files, and fixes the experimental Gemini account sign-in. Its release pull request, the subsequent main checks and the annotated v0.9.4 tag workflow are authoritative for their exact revisions and final publication. This record does not claim signing, native-package or publication results before those gates finish.

## Changes since 0.9.3

- **One archive per install (#168, PR #177).** Setup downloads the pinned kit commit once from `codeload.github.com` and checks every manifest-declared file against its size and SHA-256 before it enters the cache. A file the archive does not hold correctly, and the whole install when the archive cannot be downloaded, falls back to the per-file route. The download is resumable and uses the same bounded retries. Measured on Windows against kit revision `c191d109` (1,766 unique files, debug build, cold cache): 1,766 requests in 64.1 s before, 1 request in 25.9 s after, with 0 files left to the per-file route (`cargo test live_archive_vs_single_files -- --ignored --nocapture`).
- **Gemini account sign-in (#94, PR #176).** The sign-in terminal no longer pre-selects the auth type, which made Gemini CLI 0.63.0 sign in before its screen could ask for browser consent ("Authentication consent could not be obtained"). Verified from the pinned CLI code and a regression test; not with a real Google account, so the route stays experimental.

## Evidence

- **#176 and #177:** every required CI job was green on the revision merged, including Rust and Desktop E2E on Windows, macOS and Linux and the Candidate acceptance scenarios. One `frontend` run on #177 failed on a Playwright screenshot-capture error in an unrelated UI test and passed on rerun.
- **Local gates on Windows, per PR:** `cargo fmt --check`, `clippy --workspace --all-targets --all-features -D warnings`, `cargo test --lib account_cli::` (26 passed) and `source::` (56 passed).

## Not covered here

- Signed native packages, notarization and updater replacement are left to the tag workflow and its jobs.
- macOS has no verified Gemini account route (D-13a, D-25); the archive change is platform-neutral and is exercised by the macOS Rust and Desktop E2E jobs.
