# 0.9.2 release validation

This release reworks the image step around hoi4-imagegen, makes its install one checkbox with an automatic ChatGPT sign-in, and fixes how an install with several coding clients is applied. Its release pull request, the subsequent main checks, and the annotated v0.9.2 tag workflow are authoritative for their exact revisions and final publication. This record does not claim signing, native-package, or publication results before those gates finish.

## Changes since 0.9.1

- **One image generator, one checkbox.**
  - The image step offers only hoi4-imagegen, as a single "Install hoi4-imagegen" checkbox (unchecked means none). The other backends sit behind **Use another backend** and come from the setup package's `image_generation` row, so a new backend appears without an app release. The choice is recorded as `route_settings.hoi4_imagegen.backend`.
  - A project that records an older provider keeps it through Update and Repair. When a backend covers it, Update and repair offers to move it, and a stored key moves inside the credential store without being shown.
  - A key field is accepted by shape (a lower-case id whose upper case is a `*_KEY` or `*_TOKEN` variable, never an Anthropic, Meshy, Claude or Codex name), and a backend's `live_verified: false` and `text` settings are understood.
  - On the web, a source version with no image generator says so instead of showing an empty panel.
- **The sign-in opens by itself.** After the install the Ready screen opens the ChatGPT sign-in once per project and session. The program's notice is shown as information, and a completed sign-in is the acceptance: there is no typed answer and no confirmation screen. A failed or cancelled sign-in offers **Try again**.
- **Several coding clients in one install.** One transaction was limited to 4,096 files, but each client with its own skills copy is about 890 files. The limit now follows the manifest's own aggregate bound.
- **A kept edit survives a deselected client.** An edited file Setup keeps in a deselected client's folder was regenerated by the package's `check.py setup`. Setup now puts the kept bytes back and says so on the Ready screen.

## Evidence

- **The changes merged as #152 and #158.** All twenty CI jobs were green on each last revision, with the four candidate acceptance jobs (new, kaiserreich, recovery, clients) running the built app against the live kit manifest. The acceptance script pins the last format 5 kit revision for its older-source refusal, because the kit's latest is format 6.
- **Failures met on the way, and their causes.** The clients job failed on the transaction file bound and on the kept edit before they were fixed. The Web edition job failed on a spec pinned to a kit commit without hoi4-imagegen, now covered by a unit test and the new message. Two jobs failed only on runner errors (`ERR_NO_BUFFER_SPACE`, a kit revision change mid-run) and passed on rerun.
- **Linux, on the merged code, in WSL (Ubuntu 24.04):** install, typecheck, lint, 279 frontend tests, 807 Rust tests, web build, release build, and the desktop launch smoke test under xvfb.
- **Windows, locally:** `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `tsc`, and the frontend suites.

## Not covered here

- Signed native packages, notarization and updater replacement are left to the tag workflow and its jobs.
- A real browser sign-in through Setup's Ready screen, and a click-through of the built app on Linux, are not covered.
