# 0.9.1 release validation

This patch release makes a first install actually install hoi4-imagegen, and fixes two maintenance moves between kit revisions. Its release pull request, the subsequent main checks, and the annotated v0.9.1 tag workflow are authoritative for their exact revisions and final publication. This record does not claim signing, native-package, or publication results before those gates finish.

## Changes since 0.9.0

- **hoi4-imagegen on a first install.**
  - 0.9.0 planned no download for the `release_binary` image route on a new project or an import, because that route declares no repository command for the manifest scan to find.
  - The plan showed the provider as ready, but nothing was installed, and the lock held no release receipt. So the ChatGPT sign-in, an update and a removal could not find the install.
  - A first install now plans the same reviewed, hash-checked download that update and repair already planned, and the lock records the version and the hash of the installed files.
  - A project installed with 0.9.0 has no receipt. **Repair** installs it.
- **Case-only file renames between kit revisions.**
  - Maintenance compared the installed and incoming file lists exactly, while plan validation ignores case. A file renamed only in case (the kit's `bop_fin_*.png` and `bop_FIN_*.png`) was planned twice, as a replacement and as an obsolete removal.
  - The transaction refused the plan as "duplicate plan destination". On Windows or macOS the removal would also have deleted the file just written.
  - Maintenance now compares paths ignoring case and plans one operation per file.
- **Moving back to a `paradox_wiki/` kit revision.**
  - The emptied `hoi4_wiki/` folder is removed only after the update commits. The readiness check inside the update chose it because it existed, so it reported every required page missing and blocked the lock.
  - A wiki folder that holds pages now wins over an empty one.

## Evidence

- **The change merged as #150.**
  - All twenty CI jobs were green on its last revision, the ten required checks included.
  - The four candidate acceptance jobs (new, kaiserreich, recovery, clients) ran the built, signed app against the live kit manifest, which now declares the hoi4-imagegen v0.2.1 route.
  - Before the fix, the same jobs failed in this order: no receipt on a first install, then "duplicate plan destination" in the clients scenario, then "wiki.coverage: 11 required wiki pages are missing".
  - One run of clients and kaiserreich failed only because the kit's main moved while it ran, so the lock's revision differed from the pinned one. Their rerun on the settled main passed.
- **Regression tests.**
  - `service::builder_tests::a_first_install_with_the_hoi4_imagegen_route_installs_it_and_records_the_receipt`
  - `transaction::tests::a_case_only_rename_between_sources_is_one_operation_not_a_duplicate`, failing before the fix with two destinations
  - `transaction::tests::moving_back_to_the_paradox_wiki_folder_replaces_the_hoi4_wiki_folder`
  - `readiness::tests::a_wiki_folder_with_pages_wins_over_an_emptied_one`
- **Local runs on Windows** (on the merged branch):
  - `cargo fmt --all --check`
  - `cargo clippy --workspace --all-targets --all-features -- -D warnings`
  - `node scripts/run_rust_tests.mjs --no-fail-fast`
  - `pnpm lint`, `pnpm typecheck` and `pnpm test`
  - `scripts/validate_repository.py`

## Not covered here

- Signed native packages, notarization and updater replacement are left to the tag workflow and its jobs.
- A real browser sign-in through Setup's Ready screen is not covered.
