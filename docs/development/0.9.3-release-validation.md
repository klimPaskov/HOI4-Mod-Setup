# 0.9.3 release validation

This release moves the app-owned Meshy launcher to the Meshy MCP 0.6.9 runtime and ships the build and documentation changes merged since 0.9.2. Its release pull request, the subsequent main checks and the annotated v0.9.3 tag workflow are authoritative for their exact revisions and final publication. This record does not claim signing, native-package or publication results before those gates finish.

## Changes since 0.9.2

- **Meshy MCP 0.6.9 (#165).** The launcher accepts only the exact 0.6.9 runtime: 3,956 files, tree SHA-256 `b322d0b8a4ad03f3f0c4840462c517b79fa41ec44473a5800652c005dab6d082`. The new runtime adds `texture_model` to Image to 3D and Multi-Image to 3D and Meshy N1 retexturing. Its dependency lock differs from 0.6.7 only in the Meshy entry, and its environment reads are the same set, so the pinned child environment is unchanged. A project on the 0.6.7 runtime needs **Repair**. The kit moves its Meshy lock in klimPaskov/Agentic-HOI4-Modding#76, merged after this release.
- **Source downloads retry (#169).** A 429, a 500, 502, 503 or 504, or a dropped connection is retried up to five times with exponential backoff and jitter, or the server's Retry-After up to 30 seconds. Every file is still checked against its manifest SHA-256, and other refusals are not retried. An install fetches about 1,700 single files, so one throttled request used to fail the whole preparation.
- **Run anyway guide (#167).** `docs/RUN_ANYWAY.md` explains the Windows SmartScreen and macOS Open Anyway prompts, and the macOS statements now agree across the README and troubleshooting.
- **Candidate acceptance no longer races the kit.** A scenario takes about 25 minutes and compared the kit revision it installs with the default-branch head read at its start, so any kit merge during the run failed `new` (two reruns on 2026-11-06 failed that way while the kit merged every few minutes). The check now accepts any commit that was the default-branch head since the scenario started, found with the reviewed single-commit route. Pinned installs still compare exactly.
- **CI (#173).** A newer push to a pull request cancels its older run, documentation-only pull requests skip the heavy jobs, and pull requests run a trimmed matrix. Main and release branches keep the full matrix, so this release pull request ran all four candidate acceptance scenarios.
- **Rust 1.90 and Tauri 2.12 (#164)**, with the other crate and npm updates.
- **The azure/login action is pinned to the verified v3.1.0 release commit (#163).**
- **The README describes every tool Setup installs at the same depth (#162).**

## Evidence

- **#165:** all 20 CI jobs were green on its last revision before the merge.
- **Local source gates on Windows, on the #165 revision (main after the merge):**
  - pnpm: install (frozen lockfile), lint, typecheck, `test` (280 frontend tests), `test:manifest`, `test:release-assets`, `test:workflows`, `validate`, `validate:secrets`, `test:rust` (943 passed, 16 ignored) and `audit --audit-level high`;
  - cargo: `fmt --check`, `clippy --workspace --all-targets --all-features -D warnings`, the fuzz build check and `cargo audit`.
- **Local gates on Windows, on the merged release branch (main at 48529db plus the release commit):** `validate`, `validate:secrets`, `test:manifest` (24 tests), `test:release-assets` (42 passed, 4 skipped), `test:workflows`, `cargo fmt --check`, `clippy --workspace --all-targets --all-features -D warnings` and the Rust suite (815 passed, 16 ignored in the app crate, none failed in any crate).
- **Offline feature-assets byte ceiling against kit main e4a8007:** the test passed (the kit's slimmer `hoi4-feature-assets` skill holds the provider guidance inline, and #169 changed the test to accept either form).
- **Kit install acceptance:** the four Candidate acceptance scenarios (new, kaiserreich, recovery, clients) run on this pull request against the current kit main, which includes the fix (kit #86) for the two unterminated component markers that broke every install earlier on 2026-11-06. Their results are recorded in the pull request.
- **Meshy runtime review:** a `dist/` diff of 0.6.9 against 0.6.7 found no new network host, child process, file write or import. A live `tools/list` of the 0.6.9 runtime (initialize and tools/list only, no key) returned 28 tools.

## Not covered here

- `test:e2e`, `test:a11y` and `test:scratch-live` were not run locally. Only the feature-assets part of `test:offline` was run. Its all-component lifecycle test fails at removing `.codex/config.toml` on the kit before and after this release (issue #171). It is not part of CI or of this release's acceptance. The Desktop E2E jobs on CI cover the built app on Windows, macOS and Linux.
- Signed native packages, notarization and updater replacement are left to the tag workflow and its jobs.
- No paid Meshy call was made through the new launcher before the release. The first one is the kit's next 3D unit run.
